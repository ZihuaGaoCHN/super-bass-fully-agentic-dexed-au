# 自动音色偏好与预设上下文系统设计

日期：2026-10-07  
目标分支：`feature/local-synth-memory`

## 1. 目标

让 Super Bass Fully Agentic Dexed 在用户不需要下达“记住”指令的情况下，逐步理解其长期音色偏好，并让每个预设拥有独立、可持续、可压缩的完整语义上下文。

系统包含两层相互独立的记忆：

1. 所有预设共享的用户级 `synth.md`，只保存经过选择和提炼的长期音色偏好。
2. 每个预设独立的对话上下文，包括压缩摘要、近期完整轮次、音色操作结果和预设身份。

当前用户请求始终高于历史上下文和全局偏好。全局偏好不能替代本轮授权，例如只有当前请求明确要求时，才允许无限延音。

## 2. 已确认的产品行为

- `synth.md` 对所有预设共享。
- 每轮对话进入终态后，系统在后台自动分析可能的长期偏好；不向用户暴露“更新记忆”工具，也不要求用户说“记住”。
- 一次性的音色要求只进入当前预设上下文，不直接成为全局偏好。
- 每个预设拥有独立上下文；切换预设时，Agent 和界面切换到相应历史。
- `.dexedpreset` 携带经过压缩和脱敏的上下文，可在其他电脑继续对话。
- 传统 `.syx` 文件保持原格式和兼容性，其上下文在本机通过音色指纹关联。
- 上下文达到阈值时自动压缩；压缩失败不能丢失原文。
- 记忆整理、上下文压缩和文件 I/O 不得运行在音频线程。
- “回退”仍只恢复本轮输入前的音色状态，不回退已经完成的全局偏好整理；偏好可以通过后续自然语言纠正或忘记。

## 3. 方案选择

采用宿主管理的双层存储和后台整理器。

没有采用“主 Agent 自行调用记忆工具”，因为模型可能漏调、重复调用或把工具过程暴露给用户。没有采用纯关键词规则，因为它难以可靠区分“这次做温暖 pad”和“我通常喜欢温暖 pad”，也不利于处理中英文、否定和偏好修正。

后台整理器使用当前配置的模型生成严格 JSON 建议，宿主负责验证、合并和持久化。模型只提出建议，不能直接写文件。

## 4. 核心组件

### 4.1 `ConversationContextStore`

负责按预设身份读取、保存、迁移和删除上下文。接口不依赖 UI，也不接触音频回调。

每个预设上下文包含：

- 格式版本；
- 稳定的 `preset_id`；
- 压缩摘要；
- 最近的完整用户/助手轮次；
- 已提交音色事务的简短语义结果；
- 待压缩的轮次；
- 最近更新时间；
- 用于 `.syx` 本机关联的指纹别名。

不持久化模型推理内容、API Key、Authorization 头、原始大体积工具状态或音频数据。

### 4.2 `PresetIdentityService`

为当前音色提供稳定身份，并处理载入、另存、复制、移动和编辑。

- `.dexedpreset`：保存随机生成的 UUID；载入后恢复同一身份和上下文。
- DAW 工程状态：使用与 `.dexedpreset` 相同的嵌入格式，使工程重新打开后延续上下文。
- `.syx`：以规范化的 155 字节 DX7 音色数据计算 SHA-256 指纹。本地索引将一个或多个历史指纹映射到稳定 UUID；编辑后为同一 UUID 增加新指纹别名。
- 新初始化音色：生成新 UUID。
- 另存为 `.dexedpreset`：沿用当前 UUID 和上下文，相当于同一预设的新文件副本。
- 浏览或载入不同音色：切换至目标指纹对应的 UUID；没有命中时创建新 UUID。
- 复制预设槽位：复制音色时生成新的 UUID，并克隆上下文快照，之后两者独立发展。
- 移动槽位：移动 UUID，不复制上下文。
- 重命名：保持 UUID 不变。

### 4.3 `ContextManager`

取代每次请求开始时无条件清空 `messages_` 的行为。它为当前预设组装模型上下文：

1. 系统约束；
2. 全局 `synth.md` 偏好数据；
3. 当前预设的压缩摘要；
4. 当前预设最近的完整对话轮次；
5. 当前用户请求。

工具调用和结果必须以完整配对为单位加入或移出上下文，不能留下孤立 tool result。主请求仍受 256 KiB 请求上限约束。

初始预算建议：

- 全局偏好最多 8 KiB；
- 压缩摘要最多 24 KiB；
- 最近 8 个完整用户轮次及其助手/工具配对；
- 组装后最多 224 KiB，为协议封装保留至少 32 KiB。

预算是宿主硬限制，不依赖模型自觉遵守。

### 4.4 `ContextCompactor`

当以下任一条件成立时，在主回答完成后排队压缩：

- 当前预设完整上下文超过 160 KiB；
- 未压缩用户轮次超过 12 轮；
- 下一轮组装预计超过请求预算。

压缩输入只包含已脱敏的旧轮次和当前摘要，输出为严格结构化摘要：音色目标、已接受决定、明确拒绝项、关键参数方向、未解决问题和最近结果。摘要不能包含工具指令或新的授权。

至少保留最近 8 个完整用户轮次。压缩成功后才以原子写入替换旧摘要和被压缩轮次；失败、超时、取消、JSON 无效或落盘失败时保留全部原文，稍后重试。

### 4.5 `PreferenceCurator`

每个用户轮次进入 `completed`、`failed` 或 `cancelled` 终态后，创建非阻塞后台整理任务。为避免取消后继续产生不必要的网络调用，取消轮次只记录候选，在下一次成功请求后合并整理。

整理器输入：

- 当前用户原文；
- 当前预设已有摘要；
- 助手最终自然语言结果；
- 已有全局偏好；
- 近几轮尚未确认的偏好候选。

整理器输出严格 JSON 差异：`add`、`replace`、`remove`、`observe` 或 `none`。宿主只接受满足以下条件的写入：

- 证据是当前或待处理用户原文中的精确片段；
- 内容只涉及声音、演奏响应、调制、动态、空间感或常用工作方式；
- 没有凭据、身份信息、路径或对话指令；
- 单条不超过 512 UTF-8 字节；
- key 是稳定的规范化主题；
- 明确长期表达可以直接确认；普通一次性要求只能作为候选，至少在两个不同用户轮次重复后才晋升。

典型长期信号包括“我通常喜欢”“以后默认”“我的偏好是”“不要再给我”。“做一个空灵 pad”“这次低频多一点”属于当前预设上下文。

冲突偏好使用同一主题 key 替换旧项。整理器生成的原始证据和候选计数保存在内部元数据中，不写入 `synth.md`；`synth.md` 只包含可读的最终偏好。

### 4.6 `SensitiveDataFilter`

在写入全局偏好、预设上下文、摘要、`.dexedpreset` 或测试日志前统一运行。过滤：

- 当前模型凭据的精确值；
- `sk-`、GitHub token、云服务 Key、Bearer 头和私钥格式；
- 带密码的 URL；
- 已知本机用户目录、工作区绝对路径和 Tailscale 地址；
- NUL、非法 UTF-8、控制字符和超限数据。

命中敏感片段时，预设对话用固定占位符 `[已隐藏敏感信息]` 替换；全局偏好候选直接拒绝。过滤器是防御措施，不宣称能识别所有可能的个人信息。README 必须说明 `.dexedpreset` 会携带脱敏后的对话上下文，分享前仍应由用户检查。

## 5. 存储格式

### 5.1 全局偏好

路径保持：

- Windows：`%APPDATA%\Super Bass Fully Agentic Dexed\synth.md`
- macOS：`~/Library/Application Support/Super Bass Fully Agentic Dexed/synth.md`

内部候选、版本和维护状态存入同目录的 `memory-state.json`，不展示给模型。`synth.md` 继续使用可直接编辑的 Markdown。

### 5.2 本地预设上下文

同目录新增 `contexts/`：

- `<preset_id>.json.z`：压缩上下文；
- `preset-index.json`：`.syx` 指纹、槽位和 UUID 映射；
- 临时文件只用于原子替换，成功后不得残留。

单个解压后上下文硬上限为 2 MiB，单条消息 48 KiB，单预设近期轮次最多 32 轮。超限时先压缩；无法压缩时停止追加并显示非阻塞诊断，不能静默删历史。

### 5.3 `.dexedpreset` 和插件状态

在现有 `dexedState` XML 中增加版本化的 `agentContext` 子节点，内容为压缩 JSON 二进制和 SHA-256 校验值。旧版本忽略新节点，新版本在节点缺失时按无历史预设处理。

载入过程先完整验证格式、大小、解压上限、UTF-8、校验值和敏感数据，再修改当前上下文；验证失败时音色仍可载入，但上下文被隔离并向界面显示警告。不能因为上下文损坏而拒绝一个有效音色。

## 6. 每轮数据流

1. 用户发送消息。
2. Controller 获取当前稳定 `preset_id`，保存本轮音色回退点。
3. ContextManager 读取全局偏好、预设摘要和近期轮次，组装主模型请求。
4. Agent 执行调音并返回自然语言结果。
5. 本轮脱敏记录原子追加到该预设上下文，UI 更新该预设历史。
6. 主结果已经对用户可见后，后台队列依次执行偏好整理和必要的上下文压缩。
7. 用户切换预设时取消当前未完成主请求；已开始的持久化任务按原 `preset_id` 完成，不能写到新预设。
8. 下次进入该预设时读取最新摘要和近期轮次。

后台整理使用同一 provider/model 配置和保存的凭据，但每个轮次最多触发一次偏好整理、一次必要压缩。后台请求不提供合成器工具，不允许改变参数，也不出现在自然语言对话框中。用量和最近一次维护状态可在诊断日志查看，但不增加新的滑动菜单。

## 7. UI 行为

- 对话框只显示当前预设的自然语言用户/助手历史，不显示工具 JSON、偏好整理或压缩过程。
- 切换预设立即切换历史。
- 后台维护不弹确认框；失败只在状态区显示简短提示，例如“记忆整理将在联网后重试”。
- 保存 `.dexedpreset` 时自动携带当前预设上下文。
- 不增加新的主操作按钮。现有“发送、回退、保存为预设”保持不变。

## 8. 并发与故障处理

- 所有磁盘和后台模型请求在专用串行工作队列运行。
- 进程内 mutex 与按文件命名的 interprocess lock 保护读改写。
- 所有文件使用临时文件加原子替换。
- 每个任务捕获 `preset_id`、轮次 ID 和基线版本；版本冲突时重新读取合并，不能覆盖较新的上下文。
- Standalone 与多个 VST3 实例可共享 `synth.md`，但各自按预设 UUID 写独立上下文。
- 关闭插件时等待正在进行的本地原子写入完成；网络维护任务安全取消，并保留待处理标记。
- 缺少凭据、离线或提供商错误不影响正常音色编辑；待维护内容在后续成功连接时重试。

## 9. 隐私和信任边界

- `synth.md`、预设摘要和近期上下文会在后续请求中发送给用户选择的模型提供商。
- API Key 只通过现有安全凭据存储进入 HTTP Authorization，不进入模型消息、磁盘上下文或日志。
- 模型生成的摘要和偏好建议均视为不可信数据；宿主验证后才能持久化。
- 从外部 `.dexedpreset` 载入的上下文视为数据，不能覆盖系统约束、授权工具或改变安全策略。
- Repository、提交历史、测试固定数据和最终构建包均运行已知凭据精确匹配、通用密钥扫描和私人路径扫描。

## 10. 测试和验收

### 单元与集成测试

- 明确长期偏好自动写入；无需用户说“记住”。
- 一次性要求不写入 `synth.md`。
- 同一偏好跨两轮重复后可晋升；矛盾偏好正确替换。
- 中文、英文、否定和更正语句。
- 不同预设上下文严格隔离，切换后 UI 和模型输入一致。
- `.dexedpreset` 保存/加载往返、跨实例恢复、旧格式兼容、损坏上下文隔离。
- `.syx` 原字节不变；指纹关联、编辑别名、复制、移动、重命名符合身份规则。
- 长对话触发压缩；摘要保留接受项、拒绝项和未解决问题；最近 8 轮不被压缩。
- 压缩超时、无效 JSON、离线、关闭插件和并发版本冲突不丢数据。
- 用户、助手、工具结果和手工编辑文件中的密钥均被拒绝或脱敏。
- Context 数据不能注入系统指令或绕过无限延音约束。
- “回退”恢复音色但不跨预设、不破坏对话上下文。
- 音频线程测试确认无文件、锁、分配或网络操作。

### 真实模型与平台验证

- 真实 DeepSeek 连续三轮测试：一次性要求不记忆、明确长期偏好自动记忆、新预设正确继承全局偏好但不继承旧预设对话。
- 上下文达到阈值后的真实压缩与后续追问一致性测试。
- Windows x64：完整 CTest、Standalone、VST3 pluginval strictness 8。
- Apple Silicon：本机完整回归、Standalone、VST3 pluginval strictness 8、保存后重启和 `.dexedpreset` 往返。

### 安全扫描

- Gitleaks 扫描 feature 分支完整历史和构建包。
- 自定义递归扫描源码、二进制、ZIP/TAR 内嵌文件、测试报告、README 和更新日志。
- 使用当前环境已知 API Key 做精确字节、UTF-16LE 和 UTF-16BE 匹配。
- 检查私人绝对路径、Tailscale 地址、Authorization 头和预设测试夹具。
- 任何真实凭据命中都阻止提交或交付；测试占位值必须逐项核实并使用明显的 `DO-NOT-LEAK` 标识。

## 12. 非目标

- 不实现云同步、账户系统或跨用户共享记忆。
- 不修改 DX7 `.syx` 文件格式。
- 不保存或恢复模型隐藏推理内容。
- 不在本功能中增加记忆管理页面、滑动菜单或新的主操作按钮。
- 不承诺识别所有个人信息；提供明确文档、硬性凭据过滤和可删除的本地文件。

## 13. 完成标准

功能只有在以下条件全部满足后才可称为完成：

1. 自动选择性偏好、连续上下文、预设隔离、压缩和迁移均有通过的自动化测试。
2. Windows 全量回归、真实模型测试和 pluginval 通过。
3. Apple Silicon 本机回归、真实模型测试和 pluginval 通过。
4. 中文 README、中文更新日志和详细记忆文档与实现一致。
5. feature 分支、构建产物和报告的敏感信息扫描无未解释命中。
